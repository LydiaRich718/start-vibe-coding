Chapter 9 · Protect

Save points

Git, without a single diagram of arrows.

≈ 5 min💾 Do this early

What Git actually is

Git is an undo history for your whole project. Each time you commit, it records exactly what every file looked like at that moment. You can go back to any of those moments.

Think of it as save points in a game. You don't need the machinery, you need to know when to press save.

Commit after anything that works.
Commit before anything big.

You don't have to learn any commands. Claude does the work, you say the words:

When something works
This version works. Please set up Git if it isn't already, and commit this as a save point.
When you've broken it
Something is broken. Take me back to the last commit, and explain in simple words what went wrong.

⏰ Four seconds

That's the whole cost, and it's the difference between "oh well" and "oh no". There is no such thing as committing too often. A save point you make after you die is not much use.

🧠 Three words you'll hear

  • Commit. One saved moment in your history.
  • Push. Send your commits up to GitHub (Chapter 10).
  • Repo. Short for repository. Your project plus all its history.

Chapter 11 · Level up

Secrets & superpowers

API keys, the .env file, and putting AI inside the thing you built.

≈ 20 min🔑 The grown-up bit

What a secret is

Sooner or later your project will want to use somebody else's service: send an email, take a payment, ask an AI a question. Those services need to know it's you asking.

So they give you an API key, a long random string that works as a password:

sk-or-v1-8f3a...2c7d

🚨 An API key is a password with your credit card attached

If someone else gets yours, they use the service as you, and you get the bill. People run bots that scan GitHub for leaked keys around the clock. This is not hypothetical.

Where it goes: a file called .env

.env is short for environment. It's a plain text file in your project folder holding your secrets, one per line:

.env
OPENROUTER_API_KEY=sk-or-v1-8f3a...2c7d WEATHER_API_KEY=abc123def456

Your code says "go get OPENROUTER_API_KEY" instead of containing the key itself. The key lives in one file and never appears in the code you share.

Your code can be public
while your keys stay private.

.gitignore is what makes that true

Git records everything in your folder, including a file full of passwords if you let it. .gitignore is a list of files Git should pretend it can't see. Put .env in it and your secrets never leave your computer, no matter how many times you push.

.gitignore
.env .env.local node_modules

🧪 The two-file convention

Projects often ship a .env.example with the key names but no values, so the next person knows what to fill in. That one is committed. The real .env never is.

🧠 Why the leading dot

A filename starting with . is hidden by default on Mac and Linux, which is why you might not see it in Finder. VS Code shows it fine. Press ⌘+⇧+.Ctrl+H if you need to see hidden files.

You don't have to make these by hand:

Paste into Claude
Set this up properly for secrets: create a .env file for my API keys, make sure .env is listed in .gitignore so it never gets committed, and add a .env.example with the key names but no values. Then explain in simple words how my code will read the key.

Get a real key: OpenRouter

OpenRouter is one door to hundreds of AI models (Claude, GPT, Gemini, open-source ones) through a single key. It means the app you build can have AI in it, not just the editor you build it in.

🤔 Don't I already pay for Claude?

That's for Claude helping you build. This key is for your app doing AI things for its users. Two different jobs. Your Claude subscription can't power a website you built, any more than your Netflix account can power a cinema.

  1. Go to openrouter.ai and sign in. Google or GitHub is quickest.
  2. Click your avatar, then Keys. Or go straight to openrouter.ai/keys.
  3. Click Create Key and name it first-try.
  4. Set a spend limit on it while you're there. A key capped at $1 can cost you at most $1, even if your code goes haywire in a loop at 3am. Best habit in this chapter.
  5. Copy the key now. It's shown once. If you lose it, delete it and make another, no drama.
  6. Paste it into your .env. Not into a chat, not into a note, not into your code.

💰 Money, before you spend any

  • Signing up is free. No card needed to look around.
  • Some models are free to use, usually marked with :free in the name. Start there.
  • Paid models run on credit you add up front. Add the smallest amount they'll let you. You can't accidentally run up a bill on credit that doesn't exist.
  • Check a model's price on openrouter.ai/models before you point code at it, not after.

🌐 "It works on my computer but not on the live site"

Almost always this. .env deliberately never left your machine, so the live site has no key.

Go to vercel.com/dashboard, your project, Settings, Environment Variables. Add the same name and value there, then redeploy. Same secret, told to Vercel directly instead of through GitHub. This is how professional teams do it.

🙈 If you leak a key

Deleting the file isn't enough. Git remembers and bots scrape faster than you can undo. Go to the service, delete that key, make a new one. Thirty seconds and the leaked one is worthless. Everyone does this at least once. The only mistake is not revoking it.

Three rules that keep you safe

🔒 1. Never paste these into a chat

Passwords. API keys and secret tokens. Database passwords. Real customer names, emails or card numbers. If a project needs a key, say: "Set this up as an environment variable so the key isn't in the code."

🛑 2. If it goes off the rails, say these in order

"Stop. Don't change anything else." Then "Explain what you just changed, in simple words." Then "Undo that." You won't hurt its feelings, and you can't break your computer from a chat box.

🐢 3. Small changes beat big ones

One change, look, commit. Every time. It feels slower and it is dramatically faster.

When you get stuck

You will. Everyone does, forever.

Showing answers for

Setup won't cooperate

I can't find the Spark star in VS Code

Quit VS Code completely (⌘+Q, closing the window isn't enough)(close it from the taskbar too) and reopen. Still missing? Press ⌘+⇧+PCtrl+Shift+P and run Developer: Reload Window. Still nothing? Check the Extensions panel says Claude Code is Installed, by Anthropic.

It says I need to sign in, or my plan won't work

Claude Code needs a paid plan: Pro, Max, Team or Enterprise. Check claude.ai settings and billing that it's actually active, then sign out and back in inside VS Code.

Nothing's happening. It's just sitting there.

Give it 30 seconds. It thinks before it types, and bigger jobs take a minute. If it's genuinely frozen there's a stop button; press it and send your message again. If that fails, run Developer: Reload Window. Your files are on disk, so nothing is lost.

Do I need Node.js? Python? Homebrew?

Not to start. Claude will tell you when a project needs one and can install it with you. Don't install things just in case. That's how beginners end up with four broken versions of everything.

Claude is doing something weird

It edited my files without asking. Is that normal?

Yes. On a Pro plan it starts in Auto mode and gets on with edits inside your project. The mode is written at the bottom of the chat box.

Want to be asked first? Click it and pick Plan (it writes out its intentions and waits) or Manual (it asks before each edit). Beginners often like Plan for the first week.

It IS asking permission. Should I say yes?

Yes for creating or editing files inside your project folder. That's the job you gave it.

Ask first for deleting lots of files, working outside your folder, installing software, or sending things to the internet. Type "why do you need that?" Nothing happens until you approve.

Everything broke and I don't know what happened

Say: "Stop. Explain what changed in simple words, then undo it." If you committed, say "take me back to the last commit." This is exactly why commits exist.

There's scary red text

Red is normal, usually a warning rather than a disaster. Copy the whole thing, paste it to Claude, and say: "I got this error. What does it mean and how do I fix it?" That is genuinely what professionals do.

My change isn't showing up

Refresh the browser (⌘+R)(Ctrl+R). Still nothing? Ask: "Which exact file should I open, and what's its full path?" You're probably looking at a different copy.

Claude forgot what we were doing

Long conversations get trimmed, and a new chat starts blank. Click Session history at the top of the Claude panel to reopen an old conversation. Starting fresh? Say what you're building in one line. It reads your files anyway.

Keys, secrets and money

My site works locally but breaks live

Nine times out of ten it's a missing environment variable. Your .env never left your computer, which is the point of it. Add the same key names and values in vercel.com/dashboard, your project, Settings, Environment Variables, then redeploy.

I think I leaked an API key

Don't panic and don't try to erase history. Go to the service that issued it, delete that key, create a new one. The leaked one instantly becomes worthless. Then check .env is listed in .gitignore so it can't happen twice.

Is my code private?

What you type and the files Claude reads go to Anthropic's servers to be worked on. That's how it functions. Your GitHub repos are private unless you make them public, and Claude runs on your own machine on your own folder.

The rule that matters: never put real passwords, API keys, or real customer data in a project you're learning with. For specifics, read Anthropic's privacy policy and check the privacy settings in your Claude account.

No. It's saved in your folder. Open VS Code, File, Open Recent, pick your project, click the Spark star. Carry on.
